# Конусы дорожных работ левитируют — лог расследования

## Симптом
ClutterCone (конусы дорожных работ) визуально висят ~0.2–0.4 м над проезжей
частью. Заметно сбоку, если смотреть **параллельно дороге, с уровня ПЧ**: под
конусом видна тень на асфальте и просвет. Машина едет колёсами по дороге и НЕ
левитирует — поэтому баг казался «невозможным».

## Почему долго не находился (ложный след)
Все «физические» замеры показывали, что конус **стоит на земле**:
- `cone.global_position.y` (origin тела) ≈ коллизия дороги + 0.02
- raycast вниз по группе «Road» → коллизия дороги совпадает с origin
- `MeshInstance3D.global_transform * get_aabb()` → низ визуала == origin

Вывод «grounded» из этих замеров был **неверным**, потому что и placement, и
проверка визуала опирались на **одно и то же враньё — `get_aabb()`**. Пока
сравнение шло «конус vs коллизия дороги», баг был невидим. Нужно было сравнивать
**низ ВИДИМОЙ геометрии конуса** с **отрендеренным асфальтом**.

## Что реально решило (правильный метод)
1. **Инструментирование рендера дороги.** Дорога рисуется через
   `_rs_add_mesh(chunk_key, arr_mesh, Transform3D.IDENTITY)` — это НЕ нода
   сцены, поэтому поиск по `MeshInstance3D`/AABB её не видит (ранний тупик).
   Добавлен временный реестр `_road_visual_registry[chunk_key] = [{tk, mesh}]`
   прямо в `_finalize_road_batches_for_chunk` (vertices world-space, IDENTITY).
2. **Сэмпл высоты отрендеренного асфальта** под XZ конуса: перебор треугольников
   зарегистрированных дорожных мешей + barycentric-интерполяция Y
   (`_debug_sample_road_visual`). Это и есть «настоящий асфальт», а не коллизия.
3. **Запуск ровно в проблемной точке.** Через Godot MCP `play_scene
   mode:"res://main.tscn"`, телепорт игрока к `lat=59.144900, lon=37.939466`
   (`terr._latlon_to_local(...)` → world XZ), чтобы ClutterManager заспавнил
   конусы рядом и можно было мерить ИМЕННО те, что видит пользователь.
4. **Маркеры + скриншот.** Поставил цветные сферы на каждую измеренную высоту
   (зелёный=асфальт, синий=низ конуса) и камеру на уровень ПЧ вдоль дороги.
   На скриншоте синий маркер «cone_bottom» лежал на асфальте, а ОРАНЖЕВЫЙ КОНУС
   висел над ним. Это подтвердило: визуал выше своего же origin.

## Корневая причина (доказана числами)
Гистограмма Y **реальных вершин** меша конуса в body-local (применён
`_cone_visual_xform`, 0 = origin тела = дорога):
```
surf 0 verts=1216  body_local Y range [0.2545 .. 0.7477]
   yhist(0.05): [0.25:780] [0.30:194] [0.70:242]
```
**Самая нижняя реальная вершина конуса — на +0.2545 м над origin, а не на 0.**
Значит, поставив origin на дорогу, видимый конус висит на 0.25 м.

Почему: `_extract_pack_mesh()` определял низ модели через `mi.get_aabb()` и
центрировал базу к y=0. Но у `road_works_stylized_pack.glb` (piece index 1)
**stored AABB раздут ~0.25 м ВНИЗ** относительно реальной геометрии (мусорные
import-bounds GLTF). Низ раздутого бокса садился на дорогу → реальная геометрия
висела выше. Тот же раздутый бокс «съедал» масштаб (`s = target_h /
aabb.size.y`), делая конус мелким (0.49 м вместо 0.8 м) — отсюда «конусы
маловаты».

## Фикс
В `_extract_pack_mesh()` считать AABB модели по **фактическим вершинам**
(`surface_get_arrays(si)[ARRAY_VERTEX]`, трансформированным `mesh_in_root`), а
НЕ по `mi.get_aabb()`. После фикса проверка:
```
NEW cone body-local Y range = [0.0000 .. 0.8000]  size=(0.62, 0.8, 0.62)
```
Низ ровно в origin, полная высота. Пользователь подтвердил: «Теперь конусы на
уровне земли!!!»

## Грабли по дороге
- **`get_aabb()` врёт после фикса тоже:** мой собственный `_debug_cone_visual_bottom`
  (через `get_aabb()`) после фикса показывал «GAP=-0.41» (будто конус утоплен) —
  это раздутый бокс, а не реальная геометрия. Реальные вершины [0..0.8] — истина.
  Урок: для этой модели мерить визуал ТОЛЬКО по вершинам, не по `get_aabb()`.
- Телепорт физической машины игрока её «сносит» (она едет дальше) — мерить надо
  по `instance` из `_clutter_manager._records`, а не по «ближайшему» конусу.
- `get_first_node_in_group("osm_terrain")` после телепорта возвращал null —
  искать терреногенератор по `has_method("_debug_cones_at_latlon")`.
- Профайлер засыпает Output-лог — `print()` тонет; возвращать данные через
  `_mcp_print(...)` в результате `execute_game_script`.

## Связанный (НЕ чинённый) баг
Lada 2109 (Такси/ДПС) левитируют по другому механизму — статичная модель + 
виртуальные `VehicleWheel3D`, Model.y=0.8. См. `docs/KNOWN_BUGS.md`.

## Статус инструментирования
Временный debug-код (`_road_visual_registry`, `_debug_*`) после фикса убран из
`osm/osm_terrain_generator.gd`; реальный фикс — только в `_extract_pack_mesh()`.
